## ทำไมควรเริ่มจากงานเล็ก

เครื่องมือเขียนโค้ดด้วย AI ประเมินได้ง่ายกว่าเมื่อโจทย์มีขอบเขตชัด งานแรกควรสร้างผลลัพธ์ที่มองเห็นได้ ใช้ไฟล์ไม่กี่ไฟล์ และมีวิธีเช็กชัดเจนว่าสิ่งที่ขอทำครบหรือยัง

runbook นี้ใช้หน้า HTML แบบ static หนึ่งหน้า จุดสำคัญไม่ใช่หน้าเว็บนั้น แต่คือการฝึกวงจร **prompt → plan → review → approve → preview → verify**

## เตรียม workspace

เปิดโฟลเดอร์โปรเจกต์ว่างใน ZCode แล้วเริ่มด้วยคำสั่งที่แคบพอ ตัวอย่าง prompt นี้ตั้งใจไม่ให้เพิ่ม dependency ที่ไม่จำเป็น:

```text
สร้างหน้าแนะนำตัวขนาดเล็กไว้ในไฟล์ index.html ไฟล์เดียว
ใช้ HTML, CSS และ JavaScript แบบธรรมดาในไฟล์นั้นเท่านั้น
ห้ามเพิ่ม framework, package, CDN หรือไฟล์อื่น
ใส่ชื่อ คำแนะนำตัวสั้นๆ และปุ่มที่มีสถานะ hover ให้เห็นชัด
ใช้โทนสีขาวกับน้ำเงิน และเปิดดูได้จาก preview โดยตรง
```

ข้อจำกัดเรื่องไฟล์เดียวทำให้ตรวจผลได้ง่าย และลดโอกาสที่เครื่องมือจะสร้างงานนอกเหนือจากที่ขอ

## ตรวจแผนก่อนกดอนุมัติ

เมื่อ ZCode เสนอแผนหรือขอแก้ไฟล์ ให้หยุดตรวจดูก่อนอนุมัติ เช็กสามเรื่องนี้:

1. **ไฟล์:** แผนจะสร้างหรือแก้แค่ `index.html` หรือไม่
2. **Dependency:** มี package, CDN, script จากภายนอก หรือ asset ที่ไม่ได้ขอเพิ่มมาหรือไม่
3. **คำสั่ง:** มีคำสั่งใน terminal ที่จะรันหรือไม่ และเราเข้าใจผลของคำสั่งนั้นหรือไม่

ถ้ามีส่วนใดเกินโจทย์ ให้ถามเหตุผลหรือลดขอบเขตก่อน การกดอนุมัติคือการตัดสินใจกับการเปลี่ยนแปลงที่เห็นได้ชัด ไม่ใช่การมอบความไว้วางใจให้ทุกขั้นตอนถัดไป

## เช็กผลใน preview

หลังอนุมัติ ให้ตรวจไฟล์ที่เปลี่ยนและเปิด preview ตามตำแหน่งควบคุมของ ZCode รุ่นที่ติดตั้งอยู่ ยืนยันว่ามีชื่อ คำแนะนำตัว ปุ่ม และสถานะ hover ตามที่ขอ

ถ้า preview ไม่ตรง ให้เทียบผลกับ prompt เดิม แล้วสั่งแก้แบบ incremental โดยระบุ requirement ที่ขาด การเริ่มใหม่ทั้งหมดทำให้หาต้นเหตุของปัญหาได้ยากขึ้น

## Checklist ที่นำไปใช้ซ้ำได้

- requirement ครบทุกข้อหรือยัง
- ไฟล์ที่เปลี่ยนตรงกับที่คาดไว้หรือไม่
- มี dependency หรือ resource ภายนอกที่ไม่รู้จักเพิ่มมาหรือไม่
- มีคำสั่ง terminal รันหรือไม่ และจำเป็นจริงหรือไม่
- ผลลัพธ์ใช้งานได้ใน preview ไม่ใช่แค่โค้ดดูดีใน editor หรือไม่
- มี secret, token, URL ส่วนตัว หรือข้อมูลส่วนบุคคลโผล่หรือไม่

รายการนี้สั้นพอจะใช้ทุกครั้ง และเปลี่ยน session ที่ AI ทำงานให้กลายเป็น workflow ที่สังเกตและตรวจสอบได้

## ส่วนที่เปลี่ยนตามรุ่น

ชื่อเมนู ตำแหน่ง preview ชื่อโมเดล ขีดจำกัด และราคาอาจเปลี่ยนได้ ให้ตรวจข้อมูลเหล่านั้นจากรุ่นที่ใช้อยู่ในวันที่ทำงาน ส่วนที่คงที่ของบันทึกนี้คือการกำหนดขอบเขตงานและนิสัยตรวจงานก่อนรัน
